# Visual Brain Data Architecture

EvoForge Phase 3C replaces mock values in the React frontend with a typed, SQLite-backed telemetry pipeline that delivers real-time observability.

## API Endpoints

All endpoints are built using FastAPI and expose Pydantic typed responses:

- `/api/status`: Overall system health and workflow limits.
- `/api/agents`: Lists all agents from the `AgentRegistry` and joins against `execution_telemetry` for live stats.
- `/api/executors`: Lists all registered executors, including their dynamic health statuses and reliability profiles.
- `/api/routing/statistics`: Aggregates the `routing_decisions` table to track the historical hit rate and scores of the adaptive router.
- `/api/telemetry/executions`: Paginates historical workflow steps, including quality scores, failure triggers, and execution times.
- `/api/events/recent`: Streams the real-time event log (`SQLiteEventStore`) generated by the `EventEmitter`.
- `/api/graph/knowledge`: Connects agents and registered skills/capabilities into an interactive D3/vis.js visualization.

## Database Tables

The underlying data layer (`evoforge.db`) powers the Visual Brain:

1. `execution_telemetry`: Granular execution tracking (duration, success, fallback usage, engineering test outcomes).
2. `routing_decisions`: A log of *why* the router picked a specific model, storing candidate ranking matrices and formula weights.
3. `events`: General system event bus, logging agent interactions and lifecycle events.
4. `skills`: Records the learning and dynamic capability expansions of the agent swarm.

## Polling

The React client implements a 5-second polling interval against these endpoints to ensure high-fidelity synchronization without requiring WebSockets in Phase 3.
